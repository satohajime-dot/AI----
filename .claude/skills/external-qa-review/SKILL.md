# 独立QAレビュー（実装後の必須工程）

大きな実装・改修が終わったら、**自分のコードを自分だけで OK にしない**。独立した視点でレビューと動作確認を一度通してから完了報告する。ミスが混ざりやすい変更（データ処理・自動化・見た目に出る成果物）ほど必須。

## レビューに出す内容
1. **コード品質**: バグ・ロジック誤り・設定値・パス・境界条件・置換漏れなど。
2. **動作チェック**: 実行可能なら dry-run / テスト実行で確かめる。

## レビュー担当の選び方（環境に合わせて1つ選ぶ）
- **Claude Code の `/code-review`** を使う（同梱の最も手軽な独立レビュー）。
- または**別の子エージェントを「レビュアー」として起動**し、実装者とは別の視点で「これが間違っているとしたらどこか」を洗わせる。
- または社内で使える**外部レビュー用 CLI / ツール**があればそれを使う（各自の環境依存。無ければ上の2つで代替）。

## 原則
- 返ってきた指摘は**精査して取り込み判断する**（鵜呑みにしない・全部直す必要はない）。
- 静的レビューと実行チェックが済んでも、**最終的な「見た目」（レイアウト・字幕位置・セーフゾーン等の視覚確認）は人の目**が要る。ここは自動レビューに任せきらない。
- レビューを回せなかった場合は、その旨を正直に報告する（「レビュー未実施」を隠さない）。
