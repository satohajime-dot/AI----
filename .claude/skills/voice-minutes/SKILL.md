# 録音から議事録（話者判別つき）

対面の会議・打ち合わせ・立ち話の録音に **「誰が話したか」** を付けて、議事録に整形する。
文字起こしも声紋照合も**手元のCPUで完結**し、音声を外部サービスへ送らない。

## この仕組みを使う場面／使わない場面

- **使う**: 対面の会議、懇親会、立ち話、客先訪問。要するに**誰も自動で記録してくれない場**。
  録音を外部サービスへ上げられない場面もここに入る。
- **使わない**: Google Meet / Zoom などのオンライン会議。**自動議事録のほうが確実で速い**。
  Meet なら `meeting-notes` スキル（Geminiメモの回収）を使うこと。

## 前提（初回のみ・`setup-prereqs` の後に行う）

1. **Python パッケージ**: `pip install numpy sherpa-onnx faster-whisper`
   （Apple Silicon の Mac なら `faster-whisper` の代わりに `mlx-whisper` でもよい。速い）
2. **ffmpeg**: Windows `winget install Gyan.FFmpeg` ／ Mac `brew install ffmpeg` ／ Linux `apt install ffmpeg`
3. **声紋モデルの取得**（約100MB・アカウント登録もトークンも不要）:
   `python3 tools/speaker_id.py --download-models`
4. 動作確認: `python3 tools/speaker_id.py --help` が使い方を表示すれば準備完了。

うまくいかないときは、**どの段階で止まったかを切り分けてから**次へ進む。
`ffmpeg -version` ／ `python3 -c "import sherpa_onnx"` を個別に試すのが早い。

---

## モードA：声紋の登録（トリガー：「声紋を登録して」「話者を登録して」）

**参加者ごとに1回だけ**行う。以降の会議では登録済みの声紋が使い回される。

1. **本人の同意を取るよう促す。** 他人の声を登録する仕組みなので、
   「録音して話者判別に使う」ことを本人に伝えてから録るよう、ユーザーに必ず一言添える。
2. **30秒以上の音声を用意してもらう。** 条件は次のとおり。
   - **その人だけが話している**こと（相槌や別の人の声が入ると声紋が濁る）
   - 静かな場所。自己紹介でも、資料を読み上げるのでもよい
   - 過去の会議録音から本人の発言部分だけを切り出したものでも構わない
3. 登録する:
   ```bash
   python3 tools/speaker_id.py enroll 佐野 temp/sano-30sec.m4a
   ```
4. **出力の「まとまり」の数字を確認する。** 0.55 未満なら警告が出る。
   その場合は別人の声や雑音が混ざっているので、**録り直しを勧める**（そのまま使わない）。
5. 一覧は `python3 tools/speaker_id.py profiles` で確認できる。

**保存先は `local/voiceprints/`（gitignore 配下）。** 声紋は個人情報なので、
リポジトリにコミットしない・共有しない。ユーザーが共有しようとしたら止める。

## モードB：議事録を作る（トリガー：「録音から議事録を作って」「この録音を議事録にして」）

1. **録音ファイルを受け取る**（`temp/` 経由が基本）。参加者の名前を聞き、
   **登録済みの声紋があるか** `profiles` で確認する。無い人がいればモードAへ誘導する。
2. **文字起こし**（長い録音では数分〜数十分かかる。先に一言断る）:
   ```bash
   python3 tools/speaker_id.py transcribe temp/録音.m4a --out local/speaker_id
   ```
3. **話者の振り分け**（参加者を `--profile` で並べる）:
   ```bash
   python3 tools/speaker_id.py assign local/speaker_id/録音 --profile 佐野 --profile 安藤
   ```
   - 声紋が無い過去の録音は、代わりにアンカー方式が使える:
     `--speaker "佐野:ドーナツ全体のAI推進" --speaker "安藤:基本的に全員使ってる"`
     （**会話の中身を知っている人しか指定できない**ので、可能なら声紋登録を勧める）
4. **抜き取りで照合する（必須）。** `.assigned.txt` から**2〜3か所**選び、
   会話の流れ（質問→回答）と内容が話者名と矛盾しないか確かめる。
   `不明` が多い・話者が入れ替わって見える場合は、声紋の録り直しか
   `--margin` の調整を提案する。**確かめずに議事録へ進まない。**
5. **議事録に整形する**（`knowledge-capture` / `grasp-to-report` の作法に従う）:
   - 保存先: `company/<部署>/notes/YYYY-MM-DD-<スラッグ>.md`
   - 構成: **決定事項／保留事項／宿題（担当・期限）**
   - **文字起こしをそのまま貼らない。** 要約し、重要な発言だけ話者名つきで引用する
   - 金額・固有名・数字は**一次ソースで裏取り**してから書く（聞き取り間違いが混ざる）
6. **宿題（`- [ ]`）は該当部署の `status.md` へ転記する**（アクションアイテム昇格。notes は台帳ではない）。
7. 何を作ってどこに置いたかを、クリック可能なリンクで報告する。

## 精度について（正直に伝えること）

- 話者判別は**補助**であって正解ではない。実測（2026-08-28・3人の会議録音）では、
  別日に登録した声紋での判定が、その場のアンカー方式と **94%** 一致した。
  裏を返せば **20発言に1回はズレる**。
- **`--profile` を使うと自動でチャネル適応が走る**（1回目の結果で声紋を当日の録音側へ寄せ直す）。
  登録時とマイクや部屋が違っても効く。切りたければ `--no-adapt`。
- 短い相槌（0.8秒未満）は `短` として判定対象から外れる。これは仕様。
- **迷ったら「不明」のまま議事録に残す。** 推測で話者名を埋めない。

## 注意
- 録音・声紋登録は**本人の同意を得てから**。無断録音を助けない。
- 音声・文字起こし・声紋はすべて `local/`（gitignore 配下）に置く。共有しない。
- 業務外の私的な会話は対象にしない。
