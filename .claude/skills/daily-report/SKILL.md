# 日報の作成

「日報」と言われたら、記憶や推測で書かない。**その日の一次情報を集めてから**要約する。

## 手順

1. 材料を集める（Windows は `py`）：

   ```bash
   python3 tools/nippou.py            # 今日ぶん
   python3 tools/nippou.py 2026-07-16 # 日付指定
   ```

   拾ってくるもの: 当日TODOの完了項目（`- [x]`）／当月ワークログの当日セクション／当日の git コミット（定型を除く）。

2. **仕事に出すものだけを選ぶ。** 私用・趣味・個人開発の記録は業務報告から外す（提出先が社内なら社内業務のみ）。判断に迷う項目は、削るのではなくユーザーに一言確認する。

3. 提出用の本文に整える。**ユーザーの職場のテンプレートがあればそれに従う**（初回に「決まった書式はありますか？」と一度だけ聞き、判明したら `company/secretary/CLAUDE.md` のパーソナライズ欄に記録して次回から使う）。書式が無い場合の既定形：

   ```text
   お疲れ様です。<名前>です。

   【本日の業務内容】
   ・（成果が分かる粒度で3〜6行。「対応した」ではなく何がどうなったか）

   【次回出勤日】
   （分かる場合のみ記載）

   【一言】
   （所感を1行。不要なら削ってよい旨を添える）
   ```

4. **コピペできる形で提示する。** 送信は行わない（宛先・送信手段はユーザーの領分）。

## 原則

- 材料が空（TODO・ワークログ・コミットすべて0件）なら、「記録が見つからなかった」と正直に伝え、口頭で何をしたか聞いてから書く。**作業を捏造しない。**
- 事実ベースで書く（`grasp-to-report` スキルの原則に従う）。成果を盛らない。
- 秘書のキャラクター口調は**チャットにだけ**使う。提出する日報本文には混ぜない。
