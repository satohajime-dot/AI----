# 把握 → レポート化 → 保管

「把握して」「内容をまとめて」「整理しておいて」と頼まれたら、**口頭の要約で終わらせない**。知識として蓄積する所作を必ず実行する。

## 手順

1. **対象を読む**（巨大ファイルは全文読まず、grep→部分読み or 子エージェントに委譲して結論だけ受け取る）。
2. **事実ベースの Markdown レポートを書く**。
   - 「何の話だったか」を省略せず、丁寧に書く。
   - **資料・発言にある事実だけを書く**。予測・知ったかぶり・勝手なカテゴリ分けをしない。無い部分は「要確認」「別途」と明記する。
   - 方針・推奨・GO 条件・所感を勝手に足さない（判断はオーナーの領分）。要約と事実整理に徹する。
   - 体言止めの多用や数式の断片で圧縮せず、完全な文で書く。
3. **適切な場所に保存する**。
   - 議事録・面談・研修・カンファレンスの記録 → `library/learnings/YYYY-MM-DD-<スラッグ>.md`（`knowledge-capture` スキル参照）。
   - 部署に紐づく調査・整理 → 該当部署の `notes/` 配下。
   - 迷ったら秘書室の `inbox/` に置く。
4. **アクションアイテムを昇格する**: レポート中に `- [ ]` があれば、その場で該当部署の `status.md` へ転記する（notes は台帳ではない）。
5. **保存先を報告する**: 「どこに保存したか」を必ずクリック可能なパスで伝える。言葉だけの報告で終わらせない。

## 原則
- 一次ソース（逐語・原文）で裏を取ってから台帳化する。子エージェントや AI の要約だけで金額・契約条件・固有名を書かない。
- レビュー対象になる成果物には、確認できる URL / 場所を本文に必ず添える。
