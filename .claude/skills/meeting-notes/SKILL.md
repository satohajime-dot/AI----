# 会議議事録（Geminiメモ）の取り込み

Google Meet の「Gemini によるメモ」を回収し、**議事録＋やること（タスク）**に整形して保管する仕組み。既読管理台帳で二重回収を防ぐ。命令ひとつで初期構築でき、以降は「議事録を取り込んで」で回る。

## 前提（最初に確認）
- **Google Drive の MCP 連携**が必要（議事録本文を読むため）。できれば Google Calendar も。
- 未接続なら `/mcp` から接続を案内する（接続後は Claude Code の再起動が要ることがある）。軽く1件検索して使えるか確かめてから進む。

---

## モードA：初期構築（トリガー：「議事録の取り込みを設定して」）

1. **保存先フォルダを決める**：既定は `company/secretary/notes/meetings/`。会社案件用の部署があれば `company/<部署>/notes/meetings/` でもよい。無ければ作る。
2. **既読台帳を作る**：`<meetingsフォルダ>/harvested.json` を作成（無ければ中身は `{"harvested": {}}`）。
3. **設定を保存**：`<meetingsフォルダ>/config.json` に
   ```json
   { "folder": "company/secretary/notes/meetings", "calendar_hint": "（任意：会社カレンダーのメール等）" }
   ```
4. **Drive MCP の疎通確認**：最近ファイルを1件だけ検索してみる。ダメなら `/mcp` 接続を案内して中断。
5. 「設定できました。**『議事録を取り込んで』**で最新のGeminiメモを回収します」と伝える。

---

## モードB：取り込み（トリガー：「議事録を取り込んで」「会議メモを取り込んで」／朝の把握時）

1. **未回収のGeminiメモを探す**（使える手段で）：
   - **Google Drive MCP で検索**：タイトルに「Gemini」を含む議事録ファイル、または Google Meet 由来の自動メモ（`meet_tnfm_calendar` の印など）。まずはこれが確実。
   - Calendar MCP が使えるなら、最近の予定に添付された議事録から辿ってもよい。
2. `harvested.json` に**まだ無いものだけ**を対象にする（既読はスキップ）。
3. 各メモを **Drive MCP で本文を読み**、`knowledge-capture` / `grasp-to-report` の作法で議事録 md に整形する：
   - 保存先：`<meetingsフォルダ>/YYYY-MM-DD-<スラッグ>.md`
   - 構成：**決定事項／保留事項／宿題（担当・期限）** に分ける。事実ベースで、要約だけで金額・固有名を断定しない（一次ソースで裏取り）。
4. **宿題（`- [ ]`）は該当部署の `status.md` へ転記**する（アクションアイテム昇格。notes は台帳ではない）。
5. 回収したファイルID（と日時）を `harvested.json` に記録する（二重回収防止）。
6. **何件取り込み・どこに保存したか**を、クリック可能なリンクで報告する。

---

## 「あの会議のあの部分、どういう意味？」への対応

議事録を保管してあるので、後から「◯◯会議の△△はどういう意味だった？」と聞かれたら、該当 md を読んで**背景ごと解説**する（`grasp-to-report` と連携）。関連する過去の議事録も横断して参照してよい。

## 注意
- 業務外（個人カレンダー等）は対象にしない。
- リアルタイム監視はしない（トークンの無駄）。「取り込んで」と言われた時、または朝の把握時に1回走らせる。
- より高度な自動化（カレンダー走査スクリプト等）は各自の環境依存。まずはこの MCP ベースの回収で十分に回る。
