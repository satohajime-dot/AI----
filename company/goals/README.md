# スタンディングゴール（恒久検証）

> **「一度検証したきりのゴールは、タイムスタンプ付きの思い込みにすぎない」**
> 完了した恒久対応・再発防止策を「述語（機械チェック可能な条件）」として登録し、
> セッション開始のたびに再検証する。人の記憶ではなく機械で「静かな腐敗」を検知するための台帳。

## 運用（3行）
1. **検証**: セッション開始時に `python3 tools/verify_goals.py`（Windows は `py`）が全ゴールを再検証する。
2. **違反**: FAIL はセッション冒頭で報告する。修正は通常のタスクフローで行う（検知と修正を分ける）。
3. **卒業ルール**: 再発防止策を適用したら、**述語を書けるものはここへゴール登録してから完了報告する**。書けない対策はレポートに明記する。

## ゴールファイル形式

`company/goals/<kebab-case-name>.md`：

```markdown
---
name: ゴール名（ファイル名と同じ）
description: 1行説明
check: 検証タイプ（tools/verify_goals.py の CHECKS に登録されたもの）
os: any | windows | darwin
status: active | retired
born: YYYY-MM-DD
on_violation: 違反時の対応指示（1行）
---
# タイトル
背景・経緯の自由記述
```

## 述語のルール
- **形容詞は禁止**。スクリプトが判定できない条件はゴールにしない（「品質が高い」はNG、「必須フィールド3点が存在する」はOK）。
- 述語は**軽く・決定的・読み取り専用**であること（セッション開始毎に走るため）。
- 新しい検証タイプが必要なら `tools/verify_goals.py` の CHECKS に関数を追加する。
- フレーキー（たまに誤 FAIL する）述語は `status: retired` にして作り直す。放置は警報疲れを生む。

## 台帳
- `ledger.tsv` に全検証結果が追記される（日時・OS・ゴール・結果・備考）。
